# Side chat

A right-sidebar conversation that runs in parallel with the main conversation.
It exists so you can ask about the task — explain an error, compare approaches,
check what the main conversation is doing — without interrupting it.

## What it is

The right Sidebar hosts page types. This bundle contributes one page type,
**Side chat**, one guide card that opens it, one button in the main
conversation's header, and one composer control that quotes your selection.

Opening the tab creates (or restores) a separate Session that runs a read-only
Agent preset. The main conversation keeps running on its own; the side chat
never writes to it, never continues its unfinished work, and never changes its
state.

## Where it appears

- **Header button** — the speech-bubble control in the main conversation's
  header actions opens the side chat for that conversation and expands the
  right Sidebar.
- **Guide card** — the Sidebar's guide page lists a **Side chat** card.
- **Tab** — the side chat lives as a normal right-Sidebar tab, so it can sit
  beside files, terminals, or documents, be floated, or be split into its own
  pane.

Nothing is shown while no Session is selected, because the right Sidebar itself
does not exist without a Session.

## Quoting a selection

Select text in the main conversation, then open the side chat and use the quote
control in its composer. The control shows a compact preview — the beginning and
the end of the selection joined by an ellipsis — while the draft receives the
complete blockquote. A long selection therefore never widens or breaks the
composer row.

## What the side chat receives

Before every model step the side chat's system prompt carries:

1. its behavior rules (below);
2. the current time;
3. a bounded excerpt of the main conversation's **most recent user and
   assistant text** — no tool calls, no tool results, at most 12 messages and
   about 6000 characters, with older messages dropped.

The excerpt is read from the live main Session and refreshed when that
conversation advances. When the main conversation is not live, the side chat
says the context is unavailable instead of guessing.

## Behavior rules

The rules are part of the side chat's system prompt:

- The main conversation's history is background for understanding, not a task
  to continue. Unfinished work, todos, and running tool calls are left alone.
- A quoted fragment (a blockquote the user inserts from the main conversation)
  is the starting point of the current question and takes priority.
- When a question depends on a detail that is not in the injected background,
  the side chat says that the detail is not in the side conversation instead of
  guessing.
- Answers are direct: no greetings, no restating the main conversation. A
  reference to earlier discussion is phrased as "the main conversation
  mentioned…", not as the side chat's own memory.
- The side chat does not write its conclusions back into the main
  conversation. Only when you explicitly ask it to "bring this back to the main
  conversation" does it produce content ready to paste or summarize.

## Read-only by composition

The side Session runs the `side-chat` Agent preset, which composes only
read-only capabilities:

| Capability | Tools |
|---|---|
| Read workspace files | `read`, `read_image` |
| Search workspace files | `glob`, `grep` |
| Research on the web | `web_search`, `web_fetch` |

It has no shell, no `write`/`edit`, no patch tool, and no other tool that could
change the workspace. The guarantee comes from the preset's composition, not
from prompt wording.

## Threads and persistence

Each main conversation owns one current side thread. Its Session id is derived
from the main Session id and a generation number, and the current generation is
kept in this browser's `localStorage` under `dsh.side-chat.v1`.

- **New chat** starts a fresh thread for the same main conversation.
- Reopening the tab, or reloading the page, restores the current thread with
  its history.
- An older thread is left on disk when you start a new one; there is no cleanup
  control yet.
- The side Session is not a member of any Workspace, so it does not appear in
  the left sidebar's Session tree.

## Known limitations

- The `side-chat` preset appears in the New Session preset picker (custom group,
  last position, labelled read-only), because presets have no hidden flag.
- The side chat uses the profile's default model. The embedded composer's model
  selector can change it for that thread.
- The side chat's own Session title is generated by the title plugin and is not
  shown in this panel.
- The plugin does not offer a "send back to the main conversation" button; that
  would change the main conversation, which this plugin deliberately does not
  do.
